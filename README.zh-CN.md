# Light Reader

**一款轻量的原生 macOS PDF 阅读器，专注于英文文献翻译与批注。**

Light Reader 希望让文献阅读更简单：划词即可翻译，选中文本即可高亮，也可以直接在页面上写下笔记。你可以通过标签页同时阅读多篇文献，各文献的翻译与笔记互不干扰，批注直接保存到普通 PDF 文件中。

项目使用 Swift、SwiftUI、AppKit 和 PDFKit 构建。目前界面为简体中文，翻译功能面向英文文献到简体中文的阅读场景。

## 功能

- **划词翻译**：选中文本后，在右侧边栏查看翻译。边栏宽度可调整，默认占窗口的 25%。
- **自选翻译服务**：默认使用百度翻译，也支持兼容 Chat Completions 协议的大模型服务，可自行配置 URL、API 密钥和模型名称。
- **简洁的 PDF 批注**：右键选中的文本，添加高亮或下划线。提供浅绿色、浅橙色和浅蓝色，工具栏选色同时用于这两种批注。
- **打字机笔记**：点击 `T`，再点击页面即可输入笔记，创建后自动回到划词模式。已有笔记可以点击编辑，也可以拖动位置。
- **统一的笔记样式**：默认红色文字，字号可调。优先使用手札体，字体不可用时使用系统字体。
- **多文献阅读**：支持原生标签页、拖入文件和按文件名切换，也可以将标签页拆分为独立窗口。
- **保存与撤销**：批注保存到 PDF，支持撤销、重做，以及恢复文献上次保存的阅读位置。
- **直接输入缩放比例**：可编辑百分比，也可以使用放大、缩小和适合页面按钮。

应用不包含账号系统、托管翻译后端、OCR 引擎或文献库管理服务。翻译需要连接你配置的服务；阅读和批注在本地完成。

## 使用要求

- macOS 14 Sonoma 或更高版本。
- Apple 芯片 Mac（M1 及后续型号）。默认安装包为 `arm64`，不支持 Intel Mac。
- 百度翻译或兼容大模型服务的访问凭据。额度与费用由对应服务商管理。
- 划词翻译需要 PDF 包含可选中的文本。纯图片扫描件需要先使用其他工具进行 OCR。

安装版用户**不需要**安装 Xcode、Python、Conda，也不需要保留本项目源码。

## 安装

1. 从发布方提供的版本附件中获取并打开 `Light-Reader-<version>-macOS-arm64.dmg`，或按照下方说明自行构建。
2. 将 **Light Reader.app** 拖入 **Applications（应用程序）**。
3. 推出磁盘映像，从“应用程序”打开 Light Reader。
4. 打开**翻译设置**（`⌘,`），配置翻译服务。

未指定 Developer ID 签名身份时，本地打包脚本使用 **ad-hoc 本地签名**，不会自动完成 Apple 公证。下载的未公证版本可能被 macOS 阻止打开。仅在信任该版本时，尝试打开后前往**系统设置 → 隐私与安全性 → 仍要打开**处理提示，请勿全局关闭 Gatekeeper。

构建脚本不会自动创建公开发布版本。面向公众分发时，应完成 Developer ID 签名与公证，详见[发布与升级说明（英文）](docs/RELEASING.md)。

## 配置翻译

### 百度翻译

在翻译设置中选择**百度翻译**，填写百度通用文本翻译 API 的 APP ID 和密钥，点击**测试连接**，再点击**保存设置**。

应用将英文翻译为简体中文，单次选中的文本须小于 6,000 个 UTF-8 字节。

### 自定义大模型

选择**自定义大模型**，填写以下内容：

| 字段 | 填写内容 |
| --- | --- |
| API URL | 兼容服务的基础地址，例如 `https://your-provider.example/v1`，或完整的 `/chat/completions` 接口地址 |
| API 密钥 | 服务商提供的密钥；不需要身份验证的本地服务可留空 |
| 模型 | 服务商提供的准确模型标识 |

远程接口必须使用 HTTPS。`localhost`、`127.0.0.1` 等本机回环地址支持 HTTP。接口必须接受 Chat Completions 请求，目前不支持其他模型 API 协议。

点击**测试连接**确认可用，再点击**保存设置**。所有已打开的文献共用保存后的翻译服务配置。

## 阅读与批注

点击文件夹按钮或按 `⌘O` 打开 PDF。可以一次选择多个文件，也可以将文件拖入阅读器。只有一篇文献时也会显示文件名标签，新增文献依次显示在右侧；再次打开同一文件会切换到已有标签页。

选中文字即可翻译。需要标记时，右键选择**高亮**或**下划线**。点击工具栏颜色只会改变这两种操作使用的颜色，不会在划词时自动上色。

添加笔记时，在 `T` 旁选择字号，点击 `T`，再点击页面开始输入。点击其他位置结束编辑。空笔记在失去焦点后自动移除；清空文字后再按一次删除键，也会移除笔记。点击已有笔记可继续编辑。按 `⌘S` 将修改保存到 PDF，或使用“另存为”保留独立副本。

| 快捷键 | 操作 |
| --- | --- |
| `⌘O` | 打开 PDF |
| `⌘S` | 保存当前 PDF |
| `⌘⇧S` | 另存为 |
| `⌘W` | 关闭当前文献 |
| `⌘Z` / `⌘⇧Z` | 撤销 / 重做 |
| `⌘1` | 划词翻译模式 |
| `⌘⇧T` | 打字机笔记 |
| `⌘=` / `⌘-` | 放大 / 缩小 |
| `⌘0` | 适合页面 |
| `⌘⌥T` | 显示或隐藏翻译边栏 |
| `⌘⇧[` / `⌘⇧]` | 上一个 / 下一个文献标签页 |
| `⌘,` | 翻译设置 |

通过**窗口 → 将标签移到新窗口**可以拆分当前标签页，通过**窗口 → 合并所有文献窗口**可以合并文献窗口。

## 本地数据与隐私

安装版将用户数据保存在应用包之外：

```text
~/Library/Application Support/Light Reader/
├── credentials.json        # 大模型和百度翻译的密钥
├── settings.json           # 翻译服务配置与配置格式版本
├── settings.previous.json  # 保存已有配置时保留的上一份配置
└── reading-positions.json  # 按 PDF 路径记录的阅读位置与缩放比例
```

调试版将同样的文件保存在项目的 `.local/` 目录。翻译设置中的**打开配置文件夹**可以打开当前版本实际使用的目录。

- 密钥保存在本地 JSON 文件中，文件权限仅允许所有者访问。文件**未加密**，应用不使用 macOS 钥匙串。
- 翻译时会向所配置的服务发送选中的文本；测试连接会发送固定示例句子。应用不会上传整个 PDF 文件。
- 批注直接保存在 PDF 中，不存放在应用配置目录。
- 构建产物不应包含密钥、私人 PDF、阅读记录或项目源码。`.local/`、`.build/`、`build/` 和 `dist/` 已加入 Git 忽略规则。

首次使用安装版时，其数据目录与开发版独立。可以重新配置一次，或退出两个版本后，自行将 `.local/` 中的 `credentials.json`、`settings.json` 以及可选的 `reading-positions.json` 复制到安装版配置目录。请勿将这些文件放入发布包或提交到仓库。

## 升级

保存文献并退出 Light Reader，然后用新版本替换“应用程序”中的旧版。设置与密钥继续保存在 Application Support 中，批注继续保存在各自的 PDF 文件里。

应用标识符和安装版数据目录在版本之间保持稳定。配置文件拥有独立的格式版本，兼容最初没有版本号的格式，并在保存时保留上一份配置。遇到不支持的未来格式或损坏的配置时，会报告错误，不会静默覆盖。

目前**尚未实现**自动检查更新和应用内下载，升级需要手动完成。修改存储格式或加入自动更新功能前，请阅读[发布与升级约定（英文）](docs/RELEASING.md)。

## 从源码构建

安装 Apple Command Line Tools 或带有 Swift 工具链的 Xcode。当前项目使用 Swift tools 5.9，最低支持 macOS 14，没有第三方 Swift 包依赖。

```sh
# 开发版应用：使用项目内的配置目录。
./scripts/build.sh debug
open "build/Light Reader.app"

# 按当前 Mac 架构构建独立安装版应用。
./scripts/build.sh release
open "build/release/Light Reader.app"

# 明确指定 Apple 芯片架构。
./scripts/build.sh release arm64

# 生成 Apple 芯片应用、DMG 安装包和 SHA-256 校验文件。
./scripts/package.sh

# 运行回归检查。
./scripts/check.sh
```

打包生成以下文件：

```text
build/release/Light Reader.app
dist/Light-Reader-0.1.0-macOS-arm64.dmg
dist/Light-Reader-0.1.0-macOS-arm64.dmg.sha256
```

无论构建机器使用何种架构，打包脚本默认生成 `arm64` 版本。`./scripts/package.sh native` 按构建机器架构打包；`./scripts/package.sh universal` 保留了未来发布 Intel 版本的可能性，但 Intel 不在当前分发目标内。

回归检查会使用原生 macOS 窗口和字体，应在已登录的 macOS 桌面会话中运行。字体专项检查要求系统提供 Hannotate SC；应用本身在该字体缺失时会回退到系统字体。
